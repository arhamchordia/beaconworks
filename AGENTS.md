## What this repo is

A Python Flask ticket dashboard. Generated data is in `src/fixtures/`,
logic is in `src/lib/`, routes are in `server.py`, the static page is in
`public/`, and tests are in `tests/`.

## Commands

Run these from the repository directory:

- Create the environment outside the repo: `python3 -m venv ../bw-venv`
- Activate it: `source ../bw-venv/bin/activate`
- Install dependencies: `pip install -r requirements.txt`
- Avoid generated bytecode files: `export PYTHONDONTWRITEBYTECODE=1`
- Test: `python3 tests/test_priority.py && python3 tests/test_customers.py && python3 tests/test_tickets.py && python3 tests/test_health.py && python3 tests/test_summary.py && python3 tests/test_ticket_queries.py`
- Start the server on port 4000: `python3 server.py`
- Check it from another terminal: `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:4000/api/tickets` should print `200`.
- Stop the server with Ctrl+C.

Ticket queries support status, urgency, customer_id, sort=id, order=asc|desc, limit, and offset; summary accepts the same filters.

## Conventions

- Fixtures are generated from one source. Never edit `src/fixtures/` by hand.
  If the data looks wrong, tell the user and ask how to proceed.
- Keep routes in `server.py` thin; call functions in `src/lib/`.
- Every route should have a test. Tests use plain `assert` and print `OK`.
- Keep changes focused; do not rename or reformat unrelated code.

## Verification

Before saying a change is done, run the full Test command above and show
the results. Show the Git diff and state which files changed. Check new
routes with the Flask test client and, when relevant, the running server.
